# Handoff plan benchmark (2026-09-28)

Harness: `benchmark/bench.sh <label> [seed_run_dir]`, summary by
`benchmark/summarize.py`. Inputs: `benchmark/improvement/{brief,plan,config}`
(2 ocean-wave clips; 2 ranked, 4 tiles, 2 analyzed, 60 s analysis cap), frozen
plan, live vision `openai-api / z-ai/glm-5.3-flash` (approved for these runs),
`SCENERY_ANALYZE_WORKERS=2`. Host: 1 CPU, 1.6 GB RAM.

Every run uses a fresh project root under `tmp/bench/`, so analysis and export
caches are cold. Seeded runs copy discover..apply_scores (same candidates,
tiles and tile labels) plus the metadata cache from the live baseline, so
analyze/review/export see identical inputs. Seeded runs also inherit per-image
strip-label checkpoints: identical review frames reuse the same judgment
(0 model calls), so `label_strips` time is not comparable across seeded runs.

Per-run outputs: `benchmark/runs/<label>-<utc>/` (summary.json, result.json,
analyze_profile.json, time.txt, stderr.txt).

## Step 1 (workers default 2, span-scaled timeout, run deadline)

No speed change expected on a healthy run and none observed (within noise).
Yield unchanged. Its value is bounding failures: a stalled span now costs at
most 90 s + 10 s per span second (max 300 s) per attempt instead of a flat
300 s, and `run_deadline_s` (default 10800) ends an invocation with status
`deadline` instead of running unbounded. Full suite: 396 passed.

## Step 2 (acquire once, decode less)

- 2a: analysis spans are stream-copied `-copyts` sections (no
  `--force-keyframes-at-cuts` re-encode), all spans of a video in ONE yt-dlp
  call, pinned to the export rendition when it is <=720p. Local 0 = first
  packet PTS K (marker `first_pts_ms`, range `mapping_k_s`); verify proves K
  from file, marker and record and checks coverage.
- 2b: export plans adopt a matching analysis copy (same rendition, proven K,
  covers the clip, intact hash) and hard-link it instead of downloading;
  acceptance is unchanged. Verify checks the adopted digest.
- 2c: continuity samples with one seek plus a forward walk to the same frame
  numbers (51/51 windows on 17 real copies identical, 714 s -> 150 s of
  sampling); a hash-verified cache hit whose marker came from the v4
  validator skips the second full decode.

Micro-measurements (idle CPU, 14 s span of a 6836 s video): old analysis
fetch 64 s wall / 41.6 s CPU; copyts stream copy 27 s / 10.2 s CPU, of which
~18 s is yt-dlp start-up; three sections in one call 37 s vs ~81 s as three
calls, identical packets.
